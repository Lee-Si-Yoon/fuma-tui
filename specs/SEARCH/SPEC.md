# SPEC: Search (ZBSearch)

## Goal

Full-text search across all entries using ZBSearch (Fumadocs default search engine). No environment variables required — ZBSearch runs in-process on the server.

## Stack

| Layer | Technology |
|---|---|
| Search engine | ZBSearch (`zbsearch` package, bundled with `fumadocs-core`) |
| Server | `fumadocs-core/search/server` — `createFromSource` |
| Client | Fumadocs default `DefaultSearchDialog` (auto-wired by `RootProvider`) |
| UI | `fumadocs-ui/components/dialog/search` — `SearchDialog` |

## Architecture

```
Client (browser)                    Server (Next.js API route)
┌────────────────────┐              ┌─────────────────────────────┐
│ DefaultSearchDialog│              │ /api/search/route.ts        │
│  ↓ fetchClient     │── HTTP GET →│ createFromSource(getSource)  │
│  ↓ useDocsSearch   │              │  ↓ builds ZBSearch index     │
│  ↓ SearchDialogList │← JSON ──────│  ↓ returns ranked results   │
└────────────────────┘              └─────────────────────────────┘
```

- **Server**: `createFromSource(getSource)` creates a ZBSearch index from the dynamic obsidian source. The index is built from each page's `structuredData` (headings + content), title, description, and URL.
- **Client**: Fumadocs `RootProvider` automatically wires the default `SearchDialog` with `fetchClient()` (defaults to `/api/search`) and `useDocsSearch`. No custom client component needed.
- **No `search` prop on `RootProvider`**: The default dialog is used as-is. Fumadocs enables search by default when the `search` prop is omitted.

## Files

### `app/api/search/route.ts` — Search API endpoint

```ts
import { createFromSource } from "fumadocs-core/search/server";
import { getSource } from "@/source";

export const { GET } = createFromSource(getSource);
```

- No `revalidate` or `export const dynamic` needed — the route handler is dynamic by default since `getSource()` reads the vault at request time.

### `app/layout.tsx` — RootProvider wiring

No `search` prop is passed to `RootProvider`. Fumadocs auto-enables search with the default `DefaultSearchDialog`, which calls `fetchClient()` → `/api/search`.

## Configuration

### No environment variables

ZBSearch runs in-process — no API keys, no cloud accounts, no `.env` entries needed.

### Index content

ZBSearch indexes the following per page (from `buildIndexDefault`):

| Field | Source |
|---|---|
| `title` | `page.data.title` (frontmatter `title` or filename) |
| `description` | `page.data.description` (frontmatter `description`) |
| `url` | `page.url` (e.g., `/docs/suite`) |
| `id` | `page.url` |
| `structuredData` | Headings + content structure (from `remarkStructure` plugin) |
| `breadcrumbs` | Sidebar tree path (auto-generated from page tree) |

## Usage

- **Keyboard**: `Ctrl+K` (or `Cmd+K` on macOS) opens the search dialog.
- **UI**: Search icon in the sidebar header (provided by Fumadocs UI).
- Results show page title, description, and breadcrumb path. Clicking a result navigates to the page.

## Constraints

- The search index is built at request time from the dynamic source. For large vaults, consider switching to static mode (`staticGET`) or a cloud search provider.
- The `structuredData` is generated by `remarkStructure` (included in `fumadocs-obsidian`'s default processor). If `remarkStructureOptions: false` is set in the obsidian config, search will fail with "Cannot find structured data".
